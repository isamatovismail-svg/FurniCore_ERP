# FurniCore ERP — Руководство по E2E-тестированию (Playwright)

Настоящее руководство описывает архитектуру, структуру и порядок запуска набора сквозных (End-to-End) браузерных тестов FurniCore ERP на базе Playwright.

---

## 1. Стек и требования

- **Python:** 3.12+
- **Playwright:** 1.65.2+ (установлен в виртуальном окружении `.venv`)
- **Браузер:** Google Chrome (системный бинарник `/usr/bin/google-chrome`)
- **База данных:** PostgreSQL 16 (с демо-данными `python manage.py seed_demo`)
- **Django:** 5.1.15

---

## 2. Структура файлов E2E-тестирования

```
FurniCore ERP/
├── tests/
│   ├── test_phase6_e2e.py    # Основной E2E-тест-сьют (59 тестов, 11 классов)
│   └── ...                   # Юнит- и интеграционные тесты бэкенда (68 тестов)
├── pytest_e2e.ini            # Изолированная конфигурация pytest для E2E (без --reuse-db)
├── conftest_e2e.py           # Конфигурация фикстур E2E
├── run_e2e.sh                # Автоматический раннер: запуск сервера, прогон тестов, остановка
└── pytest.ini                # Конфигурация для бэкенд-тестов Django
```

---

## 3. Быстрый запуск

### Вариант 1. Автоматический запуск (рекомендуется)

Скрипт `run_e2e.sh` автоматически запускает dev-сервер Django на порту 8099, ожидает готовности `HTTP 200`, запускает Playwright-тесты и безопасно завершает процесс сервера по окончании:

```bash
# Запуск всех 59 E2E-тестов
bash run_e2e.sh

# Запуск конкретного тестового класса (например, RBAC)
bash run_e2e.sh -k "TestRBACUI"

# Запуск тестов адаптивности
bash run_e2e.sh -k "TestMobileResponsive or TestTabletResponsive"
```

### Вариант 2. Ручной запуск с существующим сервером

Если Django-сервер уже запущен:
```bash
# 1. Запустить сервер на порту 8099
.venv/bin/python manage.py runserver 8099 --noreload &

# 2. Выполнить E2E-тесты через отдельный pytest_e2e.ini
.venv/bin/pytest tests/test_phase6_e2e.py -v --no-header -c pytest_e2e.ini
```

## 4. Описание тестовых наборов (Test Suites)

| Класс | Описание | Количество тестов |
|---|---|:---:|
| `TestLoginAuth` | Аутентификация, валидные/невалидные креды, редиректы гостей | 4 |
| `TestDesktopPageLoad` | Загрузка всех 15 ключевых страниц при 1440×900 (без 500/404) | 15 |
| `TestTabletResponsive` | Адаптивность при 768×1024, отсутствие горизонтального скролла | 5 |
| `TestMobileResponsive` | Мобильный вьюпорт 390×844: сайдбар, гамбургер, отсутствие оверфлоу | 6 |
| `TestRBACUI` | Проверка 7 ролей системы: изоляция прав, блокировка доступа к созданию проводок | 8 |
| `TestNavigation` | Сайдбар: ссылки, сворачивание/разворачивание, подсветка активного пункта | 4 |
| `TestNoJSErrors` | Мониторинг консоли браузера на ключевых экранах | 5 |
| `TestFormInteractions` | Поиск, таблицы, канбан-доска, аналитические графики Chart.js | 5 |
| `TestProfileAndLogout` | Видимость профиля пользователя и процедура выхода из системы | 2 |
| `TestWarehousePages` | Специфика складов WH-1 (сырьё) и WH-2 (мебель), обзор складов | 3 |
| `TestAIAssistant` | Страница AI-ассистента, поле ввода сообщений | 2 |
| **ИТОГО** | | **59** |

## 5. Тестовые учётные записи для E2E

Демо-данные генерируются командой `python manage.py seed_demo`.

| Роль | Username | Назначение в тестах |
|---|---|---|
| Владелец | `owner` | Полный доступ, десктопные проверки |
| Администратор | `admin_sys` | Системный доступ |
| Бухгалтер | `accountant` | Доступ к модулю финансов |
| Начальник производства | `prod_manager` | Доступ к цехам и техкартам |
| Заведующий складом | `wh_manager` | Доступ к складам WH-1 и WH-2 |
| Менеджер продаж | `sales_mgr` | Доступ к CRM и заказам |
| Рабочий цеха | `worker1` | Доступ к производству, запрет создания фин. документов |

## 6. Регрессионное тестирование бэкенда

Для проверки того, что UI-изменения не затронули бизнес-логику:

```bash
# 1. Проверка системной конфигурации Django
.venv/bin/python manage.py check

# 2. Проверка целостности миграций
.venv/bin/python manage.py makemigrations --check --dry-run

# 3. Полный прогон всех 68 бэкенд-тестов (Фазы 2–5.5)
.venv/bin/pytest tests/ --ignore=tests/test_phase6_e2e.py -v --no-header
```
