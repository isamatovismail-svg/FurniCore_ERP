## 2. Результаты запуска Django `check --deploy`

Команда системной проверки безопасности Django в боевой конфигурации:
```bash

```

Все встроенные проверки безопасности Django пройдены с нулевым количеством замечаний.

## 3. Разграничение прав доступа преподавателя

Для исключения несанкционированного изменения системных настроек и раскрытия служебных данных:
1. **Учётная запись преподавателя (`teacher`):**
   - Назначена роль `UserRole.OWNER` — позволяет оценить все функциональные страницы фабрики (склады, цех, продажи, финансы, P&L, AI, карта).
   - **`is_staff = False`** — доступ к панели администратора `/admin/` аппаратно заблокирован Django на уровне ядра фреймворка.
   - **`is_superuser = False`** — отсутствуют права суперпользователя.
2. **Пароль учётной записи:**
   - Задаётся локально владельцем проекта через команду `python manage.py setup_teacher_account`.
   - Хранится в PostgreSQL в виде криптографического хэша PBKDF2-SHA256 с солью.
   - Не сохраняется в открытом виде, не передаётся в Git и отсутствует в кодовой базе.

## 4. Защита при работе через Cloudflare Quick Tunnel

При запуске временного публичного туннеля через утилиту `cloudflared`:
- Туннель поднимается по исходящему шифрованному каналу к серверам Cloudflare без необходимости проброса портов (Port Forwarding) на домашнем или офисном роутере.
- Порт PostgreSQL (`5435`) остаётся локальным и недоступен из глобальной сети.
- Внешний трафик перенаправляется на локальный адрес `127.0.0.1:8000`.
- Входящие запросы проверяются Django на соответствие `ALLOWED_HOSTS` (`.trycloudflare.com`) и `CSRF_TRUSTED_ORIGINS` (`https://*.trycloudflare.com`).
- Завершение процесса `cloudflared` (Ctrl+C) моментально прекращает работу внешнего адреса.
