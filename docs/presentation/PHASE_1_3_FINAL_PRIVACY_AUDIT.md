## 2. Проверка учётной записи `teacher` (`setup_teacher_account.py`)

Анализ исходного кода команды `apps/accounts/management/commands/setup_teacher_account.py` подтверждает следующие гарантии безопасности:

1. **Защита от случайного возврата роли `OWNER`**:
   - Параметр `--role` по умолчанию строго равен `UserRole.DEMO_VIEWER`.
   - При повторном вызове команды без дополнительных аргументов:
     `user.role = role` гарантированно сохраняет или переназначает роль на `DEMO_VIEWER`.
2. **Изоляция других учётных записей**:
   - Команда использует `User.objects.get_or_create(username=username, ...)`.
   - Поиск и изменение выполняются строго по ключу `username='teacher'`.
   - Учётные записи других ролей (`owner`, `admin_sys`, `accountant`, `prod_manager`, `wh_manager`, `sales_mgr`, `worker1`, `worker2`) не затрагиваются ни при каких обстоятельствах.
3. **Безопасность пароля**:
   - Открытый пароль передаётся только в системный `stdout` консоли терминала администратора в момент запуска команды для разовой передачи преподавателю.
   - В базу данных пароль записывается через стандартный вызов `user.set_password(raw_password)`, который выполняет криптографическое хэширование (PBKDF2 SHA256).
   - В коде, шаблонах, логах и Git открытый пароль не сохраняется.
4. **Защита от создания дубликатов**:
   - Поле `username` модели `AbstractUser` имеет ограничение `unique=True`. Метод `get_or_create` возвращает существующий объект (`created=False`) и обновляет его поля без создания дублирующих записей.

### 3.2 Рекомендуемая безопасная команда запуска Gunicorn

> [!CAUTION]
> **Критическое уточнение по флагу прокси:**  
> Ранее предложенный флаг `--forwarded-allow-ips="*"` **исключён** как потенциально небезопасный.  
> Поскольку Gunicorn слушает локальный интерфейс `127.0.0.1:8000`, а агент `cloudflared` подключается с того же локального хоста, стандартная конфигурация Gunicorn по умолчанию доверяет `127.0.0.1`.

**Единственно правильная команда запуска сервера:**
```bash
SERVE_STATIC=True DEBUG=False \
.venv/bin/gunicorn config.wsgi:application \
  --bind 127.0.0.1:8000 \
  --workers 2 \
  --timeout 60 \
  --access-logfile -
```

**Команда запуска туннеля Cloudflare (в отдельном терминале):**
```bash
cloudflared tunnel --url http://127.0.0.1:8000
```

## 4. Разделение по статусу достоверности

### 4.1 Подтверждено чтением исходного кода `[src]`
- Роль `DEMO_VIEWER` определена в `apps/accounts/models.py`.
- Декоратор `@deny_demo_viewer` в `apps/accounts/decorators.py` перехватывает `POST/PUT/PATCH/DELETE`:
  * Для HTMX (`HX-Request`) и AJAX (`X-Requested-With`) возвращает `HTTP 403 Forbidden`.
  * Для обычных форм возвращает `HTTP 302 Redirect` с flash-сообщением.
- Все 33 мутирующих views в 6 приложениях обёрнуты декоратором `@deny_demo_viewer`.
- 3 ранее незащищённых views (`stage_advance_action`, `order_qc_inspect`, `waste_create`) получили явные серверные проверки прав.
- Ключ OpenAI API маскируется (`sk-p...xxxx`) и не отображается в открытом виде.
- Пароли пользователей хэшируются через PBKDF2; нет ни одного view для создания/удаления пользователей в публичном интерфейсе.
- `/admin/` недоступен для пользователей с `is_staff=False`.

### 4.3 Обнаруженные особенности и риски приватности
1. **Оклады сотрудников на странице `/employees/`**:  
   Отображаются оклады сотрудников (`salary_kzt`). В контексте учебного демонстрационного стенда это синтетические тестовые данные (180 000 – 450 000 ₸). Для боевой коммерческой системы эти данные должны скрываться от неуполномоченных сотрудников.
