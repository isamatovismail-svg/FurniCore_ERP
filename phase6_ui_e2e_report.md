## 2. Обнаруженные и устранённые дефекты UI/UX

### Дефект №1: 500 Server Error на Дашборде (`VariableDoesNotExist: Failed lookup for key [username] in None`)
- **Симптом:** При открытии главной страницы `/` (Дашборд) браузер получал HTTP 500 с отладочной страницей Django. Из-за этого страница имела фиксированную ширину блока отладки ~1000px, что приводило к сбою тестов Tablet (`scrollWidth=1021px > 768px`) и Mobile (`scrollWidth=1021px > 390px`), а также скрывало боковое меню (`#sidebar`).
- **Первопричина:** В шаблоне `templates/dashboard/index.html` (строка 382) выражение фильтра `{{ mv.performed_by.get_full_name|default:mv.performed_by.username }}` приводило к вызову `mv.performed_by.username` в качестве аргумента фильтра `default:`. Если проводка совершена автоматическим фоновым процессом или миграцией без указания пользователя (`performed_by is None`), Django бросал исключение `VariableDoesNotExist`.
- **Аналогичные уязвимости устранены в:**
  - `templates/sales/detail.html` (менеджер заказа);
  - `templates/production/detail.html` (автор заказа и контролёр ОТК);
  - `templates/production/waste/list.html` (сотрудник, зарегистрировавший брак);
  - `templates/finance/accounts/account_list.html` (автор перемещения денежных средств).
- **Решение:** Заменено на безопасную конструкцию `{% if ... %}{{ ... }}{% else %}—{% endif %}`. После исправления дашборд возвращает HTTP 200, а ширина страницы точно соответствует вьюпорту (768px на планшете, 390px на смартфоне).

### Дефект №2: Горизонтальное переполнение таблиц на Складах (WH-1 и WH-2)
- **Симптом:** На странице обзора складов `templates/warehouses/index.html` таблицы остатков сырья и готовой мебели были обёрнуты в `class="overflow-auto max-h-80"`, что на некоторых мобильных устройствах не гарантировало изолированного скроллинга по оси X.
- **Решение:** Классы обновлены до `overflow-x-auto overflow-y-auto max-h-80`. Контент таблиц теперь плавно скроллится внутри карточек без распирания страницы.

### Дефект №3: Горизонтальный скролл на корневом теге HTML
- **Симптом:** При динамической отрисовке Tailwind CDN и Alpine.js на мобильных устройствах скрытый Sidebar в момент инициализации DOM мог добавлять фиктивную ширину к `documentElement`.
- **Решение:** В `templates/layouts/base.html` тегу `<html>` добавлен класс `overflow-x-hidden`.

## 4. Результаты тестирования адаптивности (Responsive Audit)

### 4.1. Desktop (1440×900)
- Полноразмерный двухпанельный интерфейс: фиксированный боковой сайдбар (256px), сворачивание/разворачивание кнопкой (`lg:w-20` / `lg:w-64`) работает корректно.
- Все карточки KPI и аналитические графики Chart.js масштабируются по 4 в ряд.
- Таблицы отображают все столбцы без скрытия данных.

### 4.2. Tablet (768×1024)
- Сайдбар по умолчанию скрыт за левым краем экрана.
- Проверена ширина содержимого: `document.documentElement.scrollWidth = 768px`, `document.body.scrollWidth = 768px`.
- Карточки KPI автоматически перестраиваются в 2 колонки.
- Таблицы сохраняют горизонтальную прокрутку внутри блоков `overflow-x-auto`.

### 4.3. Mobile (390×844 — iPhone 12/13/14)
- **Боковое меню (Sidebar):**
  - Исходное положение: `x = -230px, width = 230px` (полностью скрыто слева, `x + width <= 0`).
  - При нажатии на кнопку "Гамбургер" (`button.lg:hidden`): сайдбар выезжает в `x = 0px` с плавным переходом Alpine.js и затемнением фона (`backdrop-blur`).
  - Закрытие по клику на фон отрабатывает корректно.
- **Горизонтальное переполнение:**
  - `document.documentElement.scrollWidth = 390px` (строго 390px, 0px переполнения).
  - Карточки KPI перестраиваются в 1-2 колонки.
  - Таблицы имеют внутренний скролл без деформации мобильного лэйаута.
