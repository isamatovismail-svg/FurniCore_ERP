# FurniCore ERP — Инструкция по резервному копированию и аварийному восстановлению базы данных

**Версия системы:** PostgreSQL 16  
**Схема базы данных:** `furnicore_db`  
**Формат дампа:** Custom Compressed Archive (`.dump`, `pg_dump -Fc`)  
**Скрипты:** `scripts/backup_db.sh`, `scripts/restore_db.sh`  

---

## 1. Обзор архитектуры резервного копирования

Резервное копирование FurniCore ERP реализовано через стандартные утилиты PostgreSQL (`pg_dump` и `pg_restore`) с использованием бинарного сжатого формата (`-Fc`). Этот формат обеспечивает:
- Высокую степень сжатия данных и метаданных;
- Автоматический контроль целостности LOB (Large Objects) и блобов;
- Корректный порядок восстановления зависимостей (таблицы, внешние ключи, триггеры, индексы);
- Возможность выборочного и многопоточного восстановления;
- Аппаратную независимость дампа в рамках совместимых версий PostgreSQL.

Все дампы автоматически сохраняются в директорию `backups/`, которая добавлена в `.gitignore` и защищена от случайного попадания в Git.

## 2. Автоматическое резервное копирование (`scripts/backup_db.sh`)

### 2.1. Ручной запуск
```bash
# Создание бэкапа в стандартную папку backups/
./scripts/backup_db.sh

# Создание бэкапа в произвольную директорию (например, на внешний диск или NFS)
./scripts/backup_db.sh /mnt/backups/furnicore
```

### 2.2. Порядок работы скрипта
1. Считывает параметры подключения из переменных окружения или `.env`:
   - `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`.
2. Создаёт файл с меткой времени: `${DB_NAME}_backup_YYYYMMDD_HHMMSS.dump`.
3. Запускает `pg_dump -Fc --blobs --verbose`.
4. Вычисляет размер и контрольную сумму MD5 для проверки целостности.
5. Автоматически удаляет локальные резервные копии старше 14 дней.

### 2.3. Настройка периодического резервного копирования (Cron)
Для ежедневного ночного создания копий в 03:00 выполните:
```bash
crontab -e
```
Добавьте строку:
```cron
0 3 * * * /var/www/furnicore/scripts/backup_db.sh >> /var/log/furnicore_backup.log 2>&1
```

## 3. Восстановление базы данных (`scripts/restore_db.sh`)

### 3.1. Защита от случайного уничтожения production-данных
Скрипт `scripts/restore_db.sh` снабжён многоуровневой защитой:
1. **Обязательное указание целевой БД:** скрипт не принимает неявных параметров.
2. **Блокировка восстановления поверх production:** если в качестве целевой базы передано имя основной production-базы (`furnicore_db`), скрипт немедленно аварийно завершает работу с кодом `2`, если явно не передан флаг `--force-production`.

### 3.2. Тестовое восстановление на изолированную базу (Рекомендуется для проверок)
```bash
# Восстановление на тестовую БД furnicore_restore_test
./scripts/restore_db.sh backups/furnicore_db_backup_20261114_184204.dump furnicore_restore_test
```
*Скрипт автоматически создаст базу `furnicore_restore_test` при её отсутствии, развернёт схему, восстановит данные и выведет количество восстановленных таблиц и миграций.*

### 3.3. Аварийное восстановление на Production (Disaster Recovery)
```bash
# 1. Остановить сервисы приложения во избежание параллельных транзакций
sudo systemctl stop furnicore.service

# 2. Выполнить восстановление с флагом подтверждения
./scripts/restore_db.sh backups/furnicore_db_backup_20261114_184204.dump furnicore_db --force-production

# 3. Запустить приложение
sudo systemctl start furnicore.service
```
